# Proposed scalar `i32` WebAssembly input profile

Status: proposed capability contract and executable reference data. Drilla does
not yet implement a WebAssembly frontend.

## Module shape

The proposed first frontend slice accepts validated WebAssembly Core modules
whose selected functions have:

- zero or more `i32` parameters;
- declared mutable `i32` locals, initialized to zero by WebAssembly;
- exactly one `i32` result; and
- no imports, start function, memory, tables, globals, calls, references, WASI,
  GC, threads, SIMD, floating point, division, or conversions.

Parameters receive the invocation arguments. Values are 32-bit bit patterns.
Inputs and displayed outputs in the reference vectors are signed decimal
integers from `-2147483648` through `2147483647`. `i32.add` wraps modulo
2^32. `i32.ge_s` compares signed integers and produces canonical `0` or `1`.

## Instructions and structured control

The initial opcode whitelist is:

```text
i32.const  local.get  local.set  i32.add  i32.ge_s
block      loop       if         else     end
br         br_if
```

`local.set` may address declared non-parameter locals only. `local.tee`,
explicit `return`, and `unreachable` are excluded.

Blocks and loops have empty signatures. An `if` has `(result i32)`, no block
parameters, and a mandatory `else`. It consumes an `i32` condition: zero
selects `else`; every nonzero bit pattern selects `then`.

`br` and `br_if` may target only enclosing empty-result blocks and loops, not a
result-producing `if` or the implicit function label. Branch depth zero means
the innermost enclosing control label, counting every enclosing label even
when that label is not an allowed target. A loop label transfers to its header;
a block label transfers to its exit. Multi-value results and typed block
parameters are excluded.

Supported arithmetic does not trap. Core-invalid modules must fail WebAssembly
validation. Core-valid modules using features outside this profile must fail a
future frontend capability check rather than being silently changed or
accepted as supported.

## Reference functions

The checked-in module contains:

- `add(a, b)`: wrapping `i32.add`;
- `choose(condition, thenValue, elseValue)`: `(if (result i32) ...)`, selecting
  `thenValue` for any nonzero condition; and
- `sum(n)`: mutable zero-initialized `i` and `sum` locals, adding `i` and
  incrementing it until signed `i >= n`, matching `for (i = 0; i < n; i++)`.

Reference execution bounds `sum` inputs to signed `-1 <= n <= 10000`. This is
only a fixture execution bound. It is not a module-validation rule, a general
termination guarantee, or a runtime guard in the module. The signed comparison
makes `sum(-1)`, `sum(0)`, and `sum(1)` return `0`; the contract does not rely
on positive-domain equivalence with an unsigned comparison.

The machine-readable signed input/output vectors are in
`tests/wasm/fixtures/scalar-i32-vectors.json`.

## Proposed compiler boundary

This notation describes intent; it is **not** captured Drilla output:

```text
WASM: local.get 0; local.get 1; i32.add
IR intention: return wrapping_i32_add(parameter[0], parameter[1])
```

The fixture harness proves that established WebAssembly tools agree on the
source, committed bytes, validation, and results. It does not parse
WebAssembly, enforce this proposed frontend profile, enter Drilla IR, or claim
production frontend acceptance.

## Reproduction

After the shared pinned WABT development-shell slice is integrated, run from
the repository root:

```sh
nix develop --builders '' -c node script/verify-wasm-reference-fixtures.mjs
```

The harness:

1. checks the pinned Node major and records Node, V8, and WABT versions;
2. assembles the WAT without a debug-name section in a repository-local
   temporary directory;
3. validates generated and committed binaries with WABT;
4. requires generated bytes to equal the committed binary exactly;
5. executes the committed binary in a Node/V8 worker with an interruptible
   five-second deadline and checks every vector; and
6. requires both WABT and V8 to reject the committed one-byte-truncated binary.

Missing WABT executables and signal termination are reported as tool failures,
separately from an expected validation rejection (WABT exit status 1).
